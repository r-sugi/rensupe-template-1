# ホームページの内容を変更して公開する

利用者はエンジニアではない。SQL やコマンドの説明はせず、日本語で短く状況を伝えながら最後（公開）まで進める。詳しい仕組みはリポジトリ直下の `CLAUDE.md` を参照する。

## 最初のコピーを頼まれたとき

1. `git --version` で Git があるか確かめる。無ければ、Mac なら表示される「コマンドライン・デベロッパツール」のインストールを利用者に押してもらい、Windows なら README の「Git を入れる」を案内する。
2. 頼まれた URL を、開いているフォルダに `git clone` する（フォルダが空ならその場に `git clone <URL> .`）。
3. GitHub の認証でブラウザが開いたら、利用者に「許可」を押してもらう。

## 内容の変更を頼まれたとき

1. 内容の正本は `content/site.yaml`（文章・料金・FAQ など）と `content/photos/`（写真）だけ。D1 や Cloudflare の画面は触らない（デプロイのたびに site.yaml の内容で上書きされる）。
2. `content/site.yaml` を編集する。
   - 項目名は変えない。使える項目名は `src/content.ts` の `SETTING_KEYS` にあるものだけ。
   - コメントと字下げ（スペース2つ）を保つ。
   - 料金 `amount` は整数（円記号やカンマは付けない）。
   - 地図は `address` から自動で作られるので、住所を変えるだけでよい。
   - 空き状況は `calendar_embed_url` に、Google カレンダーの埋め込みコードの `src` の URL だけを入れる。
3. 写真は `content/photos/` にコピーする。
   - ファイル名は半角小文字。トップは `hero.jpg`、設備は `facility-01.jpg`〜`facility-09.jpg`。
   - 枚数やファイル名を変えたら、site.yaml の `photos` と `hero_image_key` も合わせる。
   - 大きい写真は長辺 2000px・5MB 以下を目安に縮小する。
4. Node.js があれば `npm ci`（初回のみ）と `npm run content:sync:local` で記入ミスを確かめる（`✖` で始まる日本語エラーが出たら直す）。Node.js が無ければこの確認は省いてよい（ミスがあれば公開時に止まり、前のページが残る）。
5. 何をどう変えたかを利用者に日本語で短く伝え、了承を得てから `main` にコミットして push する。
6. push すると Cloudflare が自動でデプロイし、2〜3分で反映される。「公開しました。2〜3分後にページを再読み込みしてください」と伝える。

## 公開が失敗したと言われたとき

利用者に Cloudflare の「Workers & Pages」→ プロジェクト →「デプロイ」の最新記録にある `✖` のメッセージを貼ってもらい、その指摘どおりに `content/site.yaml` を直して、もう一度 push する。
